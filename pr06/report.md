# ПР №6. Анализ сетевого трафика: tcpdump и Wireshark

## 1. Разбор строки tcpdump

Возьмём строку из захвата HTTP-запроса:
19:06:42.359040 IP 127.0.0.1.53992 > 127.0.0.1.8080: Flags [P.], seq 1:192, ack 1, win 512, length 191: HTTP: POST /login HTTP/1.1

| Поле | Значение | Что означает |
|------|----------|---------------|
| 19:06:42.359040 | 19:06:42.359040 | Время захвата с микросекундами |
| IP | IP | Протокол сетевого уровня (IPv4) |
| 127.0.0.1.53992 | 127.0.0.1.53992 | IP-адрес источника и порт отправителя (lo, порт 53992) |
| > | > | Направление трафика (от источника к получателю) |
| 127.0.0.1.8080 | 127.0.0.1.8080 | IP-адрес назначения и порт получателя (lo, порт 8080) |
| Flags [P.] | PSH, ACK | Флаги TCP: PUSH (немедленная передача данных) и ACK (подтверждение) |
| seq 1:192 | 1:192 | Номер последовательности: первый байт = 1, последний = 192 |
| ack 1 | 1 | Номер подтверждения (ожидаемый следующий байт от получателя) |
| win 512 | 512 | Размер окна TCP (512 байт) |
| length 191 | 191 | Длина полезной нагрузки (191 байт) |
| HTTP: POST /login HTTP/1.1 | POST /login HTTP/1.1 | Информация протокола HTTP: метод, URI, версия |

## 2. Перехваченные данные HTTP

При отправке POST-запроса с формой логина и пароля на незащищённый HTTP-сервер:
POST /login HTTP/1.1
Host: localhost:8080
User-Agent: curl/7.88.1
Content-Type: application/x-www-form-urlencoded
Content-Length: 38

username=admin&password=supersecret123

**Что видно в трафике:**  
Логин (`admin`) и пароль (`supersecret123`) передаются в теле запроса открытым текстом. Любой, кто имеет доступ к сети (например, злоумышленник в той же Wi-Fi сети, администратор сетевого оборудования, провайдер), может перехватить и прочитать эти данные.

**Кто в реальной сети может так же прочитать этот трафик:**  
- Другой пользователь в той же беспроводной сети (при использовании общедоступного Wi-Fi без шифрования).
- Владелец точки доступа (например, в кафе, аэропорту).
- Злоумышленник, подключившийся к сетевому коммутатору в режиме зеркалирования портов или использующий ARP-spoofing.
- Провайдер или администратор корпоративной сети при наличии технической возможности.

## 3. Follow TCP Stream (анализ полного диалога)

В Wireshark для пакета с POST-запросом можно выбрать *Follow → TCP Stream*. При этом отображается весь обмен данными между клиентом и сервером.

В нашем эксперименте сервер вернул ошибку `501 Unsupported method`, но сам POST-запрос с паролем перехвачен полностью.

**Что видит злоумышленник, перехвативший этот трафик:**  
- IP-адрес и порт клиента.
- IP-адрес и порт сервера.
- Время запроса.
- Полное содержимое запроса (включая логин, пароль, сессионные cookie, если они есть).
- Полный ответ сервера (включая возможно конфиденциальные заголовки).
- Злоумышленник может использовать перехваченные учётные данные для входа в систему.

## 4. HTTP vs HTTPS — сравнение

| Что наблюдаем | HTTP (порт 8080) | HTTPS (порт 443) |
|---------------|------------------|------------------|
| IP-адреса сторон | Видны | Видны |
| Порт назначения | Виден (8080) | Виден (443) |
| Заголовки HTTP | Видны полностью | Зашифрованы (не видны) |
| Содержимое запроса (body) | Видно открытым текстом | Зашифровано |
| Логин и пароль | Видны | Не видны (скрыты шифрованием) |
| Имя домена (SNI) | Видно в заголовке Host | Видно в SNI (но без пути и параметров) |

**Объяснение:**  
При использовании HTTPS всё прикладное содержимое (URL, заголовки, тело запроса) шифруется. Однако IP-адреса, порт и доменное имя (через SNI — Server Name Indication) остаются видимыми на сетевом уровне.

## 5. DNS и приватность

При захвате DNS-трафика во время посещения сайтов:
19:23:49.765488 IP 192.168.179.128.39288 > 192.168.179.2.53: A? github.com.
19:23:49.765562 IP 192.168.179.128.39288 > 192.168.179.2.53: AAAA? github.com.

**Какие домены видны в DNS даже при HTTPS:**  
`github.com`, `example.com` и любые другие домены, к которым обращается клиент.

**Что это означает для приватности:**  
Даже если сайт использует HTTPS, DNS-запросы (по умолчанию) идут в открытом виде. Таким образом, наблюдатель может узнать, какие сайты посещает пользователь, хотя детали (какие страницы, какие данные передаются) остаются скрытыми. Для повышения приватности используются DoH (DNS over HTTPS) или DoT (DNS over TLS).

## 6. Base64 

В некоторых HTTP-заголовках (например, `Authorization: Basic`) используется кодировка Base64. Декодирование строки:

```bash
echo 'dmFzeWE6TXlQYXNzd29yZDIwMjQ=' | base64 -d
Результат: vasya:MyPassword2024

Почему Base64 не является шифрованием:
Base64 — это просто способ представления бинарных данных в текстовом виде (кодировка). Он не использует секретный ключ, и любой может декодировать строку обратно. Для защиты данных необходимо использовать настоящее шифрование (например, TLS/HTTPS).

7. tshark vs tcpdump vs Wireshark
Инструмент	Когда использовать
tcpdump	Быстрый захват трафика на удалённом сервере без графического интерфейса. Поддерживает capture filters. Лёгкий, есть везде.
tshark	Консольная версия Wireshark. Позволяет применять display filters, анализировать протоколы, выводить статистику. Удобен для автоматизации и на серверах с GUI.
Wireshark	Графический инструмент для детального анализа pcap-файлов. Удобен для исследования, Follow TCP Stream, визуализации, построения графиков.
8. Каналы утечки через сеть
Какие меры защиты закрывают сетевой канал утечки:

Шифрование трафика (HTTPS, TLS/SSL, VPN) — защищает от прослушивания содержимого.

Использование DNS over HTTPS (DoH) или DNS over TLS (DoT) — скрывает доменные запросы.

Подпись кода и проверка сертификатов — предотвращает атаки «человек посередине».

Сегментация сети и использование VLAN — ограничивает зону, где возможен сниффинг.

Мониторинг сетевого трафика (IDS/IPS) — позволяет обнаружить подозрительные активности.

9. Контрольные вопросы (письменные ответы)
Что такое promiscuous mode и зачем он нужен снифферу?
Режим, в котором сетевой интерфейс принимает все пакеты, проходящие по сети, а не только адресованные ему. Необходим для перехвата трафика других узлов в широковещательном домене.

Чем отличается capture filter от display filter в Wireshark?
Capture filter применяется во время захвата (синтаксис BPF, например, port 80) и отбрасывает ненужные пакеты на уровне драйвера. Display filter применяется уже к захваченным пакетам (синтаксис Wireshark, например, http) и только скрывает их из отображения, но не удаляет.

Что такое Follow TCP Stream и для чего используется?
Функция Wireshark, которая собирает все пакеты TCP-сессии и отображает их в виде полного диалога (клиент-сервер). Используется для реконструкции переписки, поиска перехваченных паролей, анализа протоколов прикладного уровня.

Почему Base64 в HTTP Basic Auth не является защитой? Что нужно использовать вместо?
Base64 — кодировка, а не шифрование; строка легко декодируется. Вместо этого нужно использовать HTTPS (TLS), который шифрует весь канал связи.

Какие данные утекают даже при использовании HTTPS? Как это исправить?
IP-адреса (скрываются только через VPN/Tor), доменные имена в SNI и DNS-запросах. Исправление: DoH/DoT для DNS, VPN для скрытия IP, ECH (Encrypted Client Hello) для SNI.

Сисадмин говорит: «у нас свитч, а не хаб — значит сниффинг невозможен». Он прав?
Не полностью. В коммутируемой сети сниффинг трафика других узлов невозможен напрямую, но возможны атаки: ARP-spoofing, MAC-flooding, использование порта-зеркала (SPAN) администратором, компрометация самого коммутатора.

Напишите фильтр tcpdump который перехватывает только DNS-запросы (UDP порт 53) от конкретного IP 192.168.1.50.
sudo tcpdump -i eth0 -n 'udp port 53 and src host 192.168.1.50'
